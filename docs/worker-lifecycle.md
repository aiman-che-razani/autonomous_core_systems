# Worker lifecycle

Registration creates HEALTHY with capacity, capabilities, credential hash and timestamps. A heartbeat updates last_seen. Configurable thresholds move HEALTHY to SUSPECT, then DEAD. A returning authenticated worker can become HEALTHY again (recorded as `worker_recovered`), but cannot resurrect expired attempt tokens. DRAINING stops new claims and keeps renewing/finishing current jobs; draining is idempotent and refused for a DEAD worker. The normal worker exits when all local slots drain.

Each live process must have a unique worker ID; leave WORKER_ID unset to generate one. A different credential cannot take over a live ID. A process restarted with a fixed ID can re-register only after the previous holder is DEAD (`worker_reregistered`, ADR 007). Registration replay with the same session token is safe after an ambiguous response. Bootstrap credentials are shared by trusted workers; session credentials isolate ownership but are not a multi-tenant identity provider.

Heartbeats do not prove failure: pauses, overload and partitions can look like death. Work is recovered by lease expiry, not merely a suspicion event. A lease cannot be renewed before its attempt starts, and renewals are capped at task timeout plus five seconds from start, so a blocked executor cannot hold a job indefinitely. The heartbeat task is supervised: if it fails (for example, the session was revoked), the worker stops its slots and exits with the error. A 404/409 on a job route drops only that job; a result the coordinator rejects (413/422) is reported as a permanent failure instead of crashing the worker. On Linux, SIGTERM/SIGINT stops local claiming and lets active jobs finish; no server-side DRAINING state is recorded, so the row later becomes SUSPECT/DEAD. Abrupt kill is handled by lease recovery. Windows forced termination is also a crash, not graceful draining.
