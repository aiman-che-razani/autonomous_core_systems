# Security and deployment

The client bearer token controls job/operations access. A distinct worker bootstrap token authorizes enrollment. Each worker creates a random session credential, sends it on registration, and authenticates later requests with X-Worker-Session; only its hash is stored. Reusing a live ID with a different credential is rejected; a DEAD ID may be re-registered, which revokes the old session. Tokens are compared as bytes in constant time, so malformed (non-ASCII) credentials get 401 rather than a server error. Treat bootstrap credentials as privileged and admit only trusted workers: any holder can register workers, claim jobs for the tasks it advertises, read their arguments and report their results.

Requests are capped at 128 KiB with a ten-second body-read deadline. Task names/arguments, output size, metadata, retries, priorities, capacity, timeouts and pagination offsets are bounded, and NUL characters (which PostgreSQL cannot store) are rejected at the API. Values the database still refuses return 422. SQLAlchemy parameters avoid SQL interpolation of client data, and the engine hides bound parameters from error messages so job data does not reach logs. Runtime tasks cannot select executable code, arbitrary URLs or file paths, and task subprocesses run with a minimal environment that excludes the worker token. The external-sink demo is a developer-run simulation, not an API capability.

Admission rate/queue limits are global across coordinators. Authenticated read endpoints and enrollment also need an edge proxy rate policy for an internet-facing deployment; no public multi-tenant service is claimed. Metrics and results require client auth. The coordinator only answers requests whose Host header is in ALLOWED_HOSTS (loopback and the Compose service name by default), which blocks DNS-rebinding pages from reaching even the unauthenticated `/health` and `/docs`. Dashboard tokens stay in page memory. Same-origin script policy, no-store and nosniff headers apply; Swagger docs (`/docs`, `/redoc`) use a separate policy for their bundled CDN assets and are unauthenticated.

Compose binds the API to loopback and keeps PostgreSQL private. The coordinator connects as `greyqueue_app`, a least-privilege role with SELECT/INSERT/UPDATE on application tables only: no DELETE, TRUNCATE or DDL, no access to `alembic_version`, not a superuser. The one-shot `db-roles` service creates or updates that role after every migration (`docker/db-roles.sql`), so volumes created before it existed are upgraded on the next `up`; its password is passed as a session setting, never as a process argument. Only the migration and `db-roles` containers hold the owner password. Workers receive only their bootstrap credential, not database/client credentials; the migration container receives only the database URL, and the coordinator receives explicit settings rather than the whole `.env`. Coordinator, worker and migration containers run as a non-root user with read-only roots, tmpfs scratch, dropped capabilities, no-new-privileges and PID/memory limits. Base images and CI actions are pinned by digest/commit. Default subprocess execution is killable; process isolation is not a hostile-code sandbox.

For remote deployment terminate TLS at a trusted proxy or use Uvicorn certificate/key options, set REQUIRE_TLS=true, add the public hostname to ALLOWED_HOSTS, and configure trusted proxy addresses deliberately (`--proxy-headers` with a narrow `--forwarded-allow-ips`). Never trust arbitrary forwarded scheme headers. Rotate secrets through the deployment secret store, restrict database roles/network access, back up PostgreSQL and validate restore procedures. Repository `.env` and `.runtime` are ignored; CI uses explicit nonproduction credentials.

## Known gaps

- **The native development cluster still uses its owner role.** `scripts/local_db.py` creates a single superuser, which tests and experiments need in order to create and drop their disposable schemas. It is loopback-only and for development; Compose is the deployment path and uses the least-privilege role.
- One static client token with no scopes or rotation; the worker bootstrap token is full data-plane trust (see above).
- No rate limiting beyond global submission admission.
- A crashing task's last 1,000 stderr characters become the attempt error, visible to clients; tasks must not print secrets.
- No retention: job arguments, results and errors persist until an operator removes them.
